# راه‌اندازی روی سرور

> **هنوز آماده نیست (مرحلهٔ بعد):** صفحهٔ ورود با پیامک، صفحهٔ «اتصال ربات»، صفحهٔ افزودن عضو، فهرست واقعی «منتظر تأیید» و تأیید کارت‌ها در سایت (سایت هنوز دادهٔ نمونه نشان می‌دهد)، انتخاب پروژه از داخل ربات، و اسکریپت پشتیبان‌گیری. تا آن موقع پیام‌ها بایگانی و فهمیده می‌شوند، ولی جایی برای دیدن و تأییدشان نیست و کسی هنوز نمی‌تواند به ربات وصل شود.

## پیش از هر چیز: چه چیزهایی باید آماده کنید (برای صاحب‌کار)

| چه | کار کیست | نکته |
|---|---|---|
| سرور در ایران (حداقل ۴ گیگابایت RAM، ۴۰ گیگابایت دیسک) | صاحب‌کار تهیه می‌کند | همان سروری که دارید؛ یک سرور دوم هم برای نسخهٔ پشتیبان لازم است |
| دامنهٔ ‎.ir و گواهی HTTPS | صاحب‌کار می‌خرد، برنامه‌نویس وصل می‌کند | دامنه از nic.ir |
| یک سرور کوچک خارج از ایران (۱ گیگابایت RAM) | صاحب‌کار می‌خرد | برای ربات تلگرام و هوش مصنوعی؛ معمولاً با کارت خارجی یا از طریق واسطه |
| حساب OpenAI و کلید API | صاحب‌کار | شمارهٔ موبایل و کارت غیرایرانی می‌خواهد؛ شارژ اولیه و سقف خرج ماهانه بگذارید |
| حساب SMS.ir، احراز هویت، شارژ، و قالب کد ورود | صاحب‌کار | تأیید قالب چند روز طول می‌کشد؛ زود شروع کنید |
| ربات بله (از @botfather در بله) | صاحب‌کار یا برنامه‌نویس | ربات تلگرام اختیاری است |
| ۱۰ ویس واقعی از کارگاه، با متن درست هر کدام | صاحب‌کار یا سرکارگر | برای انتخاب بهترین مدل تبدیل ویس به متن |

**هزینه:** OpenAI به ازای هر دقیقه ویس و هر پیام هزینه می‌گیرد و SMS.ir به ازای هر پیامک ورود. در OpenAI حتماً سقف خرج ماهانه بگذارید و ماه اول مصرف را ببینید.

**آنچه ربات هنوز نمی‌فهمد:**
- حرف‌های داخل فیلم (فیلم فقط بایگانی می‌شود و ربات همین را به فرستنده می‌گوید).
- محتوای PDF و فایل نقشه (فقط نامش و توضیحی که کنارش نوشته شود).
- چند عکسی که با هم (آلبوم) فرستاده شوند: هر عکس یک مورد جدا در «منتظر تأیید» می‌شود.
- اگر یک پرداخت را هم با ویس و هم با عکس رسید بفرستید، دو پیش‌نویس می‌سازد؛ هنگام تأیید یکی را رد کنید.

**حریم خصوصی:** ویس‌ها، متن‌ها و عکس رسیدها برای فهمیده شدن به OpenAI (خارج از ایران) فرستاده می‌شوند. از OpenAI خواسته‌ایم پاسخ‌ها را نگه ندارد، ولی طبق قوانین خودش ممکن است داده را تا مدتی برای کنترل سوءاستفاده نگه دارد. فایل اصلی فقط روی سرور خودتان در ایران می‌ماند. پیش از شروع، این را بپذیرید.

## بخش‌های سیستم (برای برنامه‌نویس)

| بخش | کجا | چه می‌کند |
|---|---|---|
| سایت + دیتابیس + فایل‌ها | سرور ایران | Next.js و Supabase خودمیزبان (Postgres، ورود با پیامک، بایگانی فایل) |
| ربات بله | همان سرور ایران | پیام‌های بله را می‌گیرد و پاسخ «فهمیدم: …» را می‌فرستد |
| رله | سرور خارج | ربات تلگرام، تبدیل ویس به متن و فهمیدن پیام‌ها با OpenAI |

هنگام کار، همهٔ ارتباط‌ها را رله شروع می‌کند (رله به سایت). سرور ایران به خارج وصل نمی‌شود.
هر درخواست بین رله یا ربات و سایت امضا می‌شود (HMAC، با زمان و جلوگیری از تکرار).

**هنگام نصب** Docker Hub و npm ممکن است از ایران در دسترس نباشند. از mirror داخلی سرویس‌دهندهٔ ابری خود استفاده کنید، یا imageها را بیرون بسازید و منتقل کنید.

## ۱. سرور ایران

پیش‌نیاز: Docker و Node.js نسخهٔ ۲۲٫۹ یا بالاتر (برنامه‌ها تنظیم‌ها را خودشان از `.env.local` می‌خوانند و این به همین نسخه نیاز دارد).

1. **Supabase خودمیزبان** (Docker) را راه بیندازید. بعد migrationها را به ترتیب نام فایل اجرا کنید. این حلقه **فقط یک بار و روی دیتابیس خالی** است؛ migrationهای بعدی را تک‌تک اجرا کنید:

```bash
for f in supabase/migrations/*.sql; do psql "$DB_URL" -v ON_ERROR_STOP=1 -f "$f"; done
```

2. **ورود با پیامک:**
   - در SMS.ir یک قالب کد تأیید بسازید، مثلاً «کد ورود دفتر ساختمان: #CODE#». شمارهٔ قالب را در `SMSIR_TEMPLATE_ID` سایت بگذارید.
   - یک راز برای hook بسازید (باید base64 باشد):

```bash
echo "v1,whsec_$(openssl rand -base64 32)"
```

   - همین مقدار را هم در `SEND_SMS_HOOK_SECRET` سایت بگذارید و هم در env سرویس auth در Supabase:

```bash
GOTRUE_EXTERNAL_PHONE_ENABLED=true
GOTRUE_SMS_AUTOCONFIRM=false
GOTRUE_SMS_OTP_EXP=120
GOTRUE_HOOK_SEND_SMS_ENABLED=true
GOTRUE_HOOK_SEND_SMS_URI=https://your-domain.example/api/hooks/send-sms
GOTRUE_HOOK_SEND_SMS_SECRETS=v1,whsec_...
```

   به‌جای `your-domain.example` دامنهٔ سایت خودتان را بگذارید. محدودیت تعداد پیامک (`GOTRUE_RATE_LIMIT_SMS_SENT`) را هم کم نگه دارید.

3. **سایت:** فایل `.env.example` را به `.env.local` کپی کنید و پر کنید. رازهای `RELAY_SECRET` و `BALE_BOT_SECRET` را این‌طور بسازید:

```bash
openssl rand -hex 32
```

   سایت را بسازید و اجرا کنید (پشت nginx با HTTPS):

```bash
npm ci && npm run build && npm start
```

   - سایت را **فقط در یک نمونه** اجرا کنید (نه cluster و نه چند کانتینر). جلوگیری از تکرار درخواست‌های امضاشده در حافظهٔ همان یک فرایند نگه داشته می‌شود.
   - سایت را روی ریشهٔ دامنه بگذارید (مثلاً `https://daftar.example.ir`)، نه زیر یک مسیر مثل `/daftar`.
   - در nginx سقف حجم درخواست را فقط برای مسیر دریافت پیام بالا ببرید، وگرنه هر عکس یا ویس بزرگ‌تر از ۱ مگابایت رد می‌شود:

```nginx
location /api/internal/ingest {
    client_max_body_size 60m;
    proxy_pass http://127.0.0.1:3000;  # با همان تنظیم‌های proxy بقیهٔ سایت
}
```

4. **ربات بله:** توکن را از @botfather در بله بگیرید و در `BALE_BOT_TOKEN` بگذارید. ربات را اجرا کنید و با systemd یا pm2 همیشه روشن نگه دارید (تنظیم‌ها را از `.env.local` می‌خواند):

```bash
npm run bale-bot
```

## ۲. رله (خارج از ایران)

یک سرور کوچک با Node.js نسخهٔ ۲۲٫۹ یا بالاتر. پروژه را با `git clone` روی آن بیاورید و یک `.env.local` بسازید با این مقدارها:
- نشانی سایت در ایران: `CORE_URL`
- راز رله، همان مقداری که روی سایت است: `RELAY_SECRET`
- کلید OpenAI: `OPENAI_API_KEY`
- توکن ربات تلگرام، اگر ربات تلگرام می‌خواهید: `TELEGRAM_BOT_TOKEN`
- مدل تبدیل ویس به متن، بعد از بخش ۳: `STT_MODEL` (تا آن موقع پیش‌فرض `gpt-transcribe`)
- مدل فهمیدن پیام‌ها: `AI_MODEL` (پیش‌فرض `gpt-6-astra`؛ پیش از شروع مطمئن شوید با کلید شما در دسترس است)

اجرا (با systemd یا pm2 همیشه روشن):

```bash
npm ci && npm run relay
```

**این سرور حساس است:** کلید OpenAI و راز رله روی آن است و هر کس به آن دسترسی پیدا کند می‌تواند جای رله کار کند. فقط با کلید SSH وارد شوید، ورود با رمز را ببندید، و دسترسی را به خودتان محدود کنید. اگر فکر می‌کنید لو رفته، `RELAY_SECRET` را روی هر دو طرف و کلید OpenAI را عوض کنید.

## ۳. انتخاب مدل تبدیل ویس به متن (روی سرور رله)

این کار روی رله انجام می‌شود، چون OpenAI از ایران در دسترس نیست.

۱۰ ویس واقعی را در یک پوشه بگذارید. کنار هر کدام یک فایل `.txt` با متن درستش بگذارید (با همان نام: `v1.ogg` و `v1.txt`). بعد اجرا کنید:

```bash
npm run stt-eval -- samples/voices gpt-transcribe gpt-4o-transcribe gpt-4o-mini-transcribe whisper-1
```

نتیجه در `samples/voices/stt-results.tsv` ذخیره می‌شود: متن هر مدل، زمانش و درصد خطا. مدل برنده را در `STT_MODEL` رله بگذارید. در مقایسه، به درست‌بودن **عددها و مبلغ‌ها** بیشتر از بقیهٔ کلمه‌ها اهمیت بدهید؛ درصد خطا همهٔ حرف‌ها را یکسان می‌شمارد.

پیش از اولین اجرا، مطمئن شوید نام مدل پیش‌فرض با کلید شما در دسترس است.

## ۴. اتصال افراد به ربات

1. صاحب‌کار شمارهٔ سرکارگر، حسابدار یا ناظر را به پروژه اضافه می‌کند. **صفحهٔ افزودن عضو هنوز ساخته نشده.**
2. هر نفر در ربات `/start` را می‌فرستد و دکمهٔ «ارسال شمارهٔ خودم» را می‌زند (فقط از گوشی).
3. در سایت وارد می‌شود و از بخش «اتصال ربات» کد شش‌رقمی می‌گیرد. **این صفحه هم هنوز ساخته نشده.**
4. کد را ظرف ده دقیقه در ربات می‌نویسد.

شماره باید همان شماره‌ای باشد که با آن وارد سایت می‌شود. از آن به بعد هر ویس، عکس، فایل یا پیامی که بفرستد بایگانی می‌شود و در «منتظر تأیید» می‌آید. فقط صاحب‌کار می‌تواند تأیید کند.

ربات‌ها فایل بزرگ‌تر از ۲۰ مگابایت را نمی‌گیرند و به فرستنده می‌گویند کوتاه‌ترش کند. ویس بلند را چند تکه بفرستید. (این سقفِ تلگرام است؛ برای بله فرض شده و باید آزمایش شود.)

کسی که در چند پروژه عضو است، فعلاً پیامش به اولین پروژهٔ باز او می‌رود و پاسخ ربات نام پروژه را می‌گوید. انتخاب پروژه از داخل ربات در مرحلهٔ بعد می‌آید.

## ۵. آزمایش نهایی

این آزمایش بعد از مرحلهٔ بعد (صفحهٔ ورود و «اتصال ربات») شدنی است، چون تا آن موقع کسی نمی‌تواند به ربات وصل شود.

یک ویس آزمایشی به ربات بفرستید. باید اول «دریافت شد» بیاید، بعد پیام «فهمیدم: …»، و مورد در «منتظر تأیید» سایت ظاهر شود. اینترنت بین‌الملل سرور ایران را یک بار قطع و وصل کنید: پیام‌ها نباید گم شوند، فقط دیرتر می‌رسند.

## ۶. پشتیبان‌گیری (پیش از دادهٔ واقعی)

**پیش از ورود دادهٔ واقعی** باید راه بیفتد:
- پشتیبان روزانه از دیتابیس (`pg_dump`) و فایل‌ها، با نسخهٔ دوم روی سرور دیگر.
- هر ماه یک بار بازگردانی آزمایشی.

اسکریپتش هنوز آماده نیست. تا آن موقع پشتیبان را دستی با `pg_dump` بگیرید.
